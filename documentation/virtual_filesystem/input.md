# INPUT FS

Filesystem for handling events from the input devices connected to the system like keyboard, mouse,...

## Location
For now /input, but will move to /dev/input in the future.

## Structure:
`input/all` -> aggregated events from all input devices
`input/<device>` -> events from a specific input device, where `<device>` is the name of the device (e.g. keyboard, mouse, controller)
`input/<device_id>` -> events from a specific input device, where `<device_id>` is the id of the device (will at some point be connected to /dev/somewhere devices)

The structure of a generated evnet:
```
#[repr(C)]
struct InputEvent {
    generated_at: FfiInstant,
    code: u32,
    value: u32,
}

#[repr(C)]
struct FfiInstant {
    seconds: u64,
    nanos: u32,
}

```

## Event delivery:
Note: When any client opens an input file, events will stop being delivered to the kernel TTY.
Each client recieves its own event buffer. One client consuming the events does not affect other clients. The events are delivered in the order they are generated by the kernel.
New events can be written directly into the file and they will be placed at the end of the buffer for all clients (including the one that generated the event)
The event queue has space for 64 events for each client (by default). If there is no space, new events are dropped
